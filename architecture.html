Grounded Finance Assistant

Architecture walkthrough — TBX / BVP Tech Catalyst.

The model decides what to compute. Postgres computes it. The model's words are then checked against the result before anyone sees them. No number the assistant states can originate from the model.

01The decision everything follows from

The obvious build is text-to-SQL: let the model write a query, run it, show the answer. We deliberately did not. The problem statement rules it out in one sentence — “aggregate the data correctly before handing results to the language model, so the model explains a computed result rather than calculating one itself.”

Can emit invalid SQL?YesNo — Python writes the SQL

That reframe is also why a 7B model is viable: we ask it to do extraction, not generation. Filling a fixed schema is what small models are good at. The 20 % model-efficiency criterion turns from a constraint into an advantage.

02The request pipeline

The ordering has a deliberate consequence for the UI. Rows are emitted at the Postgres step, before narration begins — so real numbers appear on screen at ~3.7 s while the prose is still being written. It reads as fast, and it reinforces visually that the figures came from the database.

03Where wrong answers get stopped

Accuracy and grounding is the largest single criterion at 30 %. Five layers, each cheap, each catching a different failure. Every figure below was measured against our 1,019,354-row build.

Layer 4 is the one worth explaining slowly

Ambiguity is not a property of the question — it is a property of the question against this data. “How much did we spend last month” is ambiguous in principle (paid vs committed); if pending is zero that month it is not ambiguous in fact, and asking is friction.

So we never ask the model whether something is ambiguous. We detect candidate readings with rules, run each one as a cheap scalar query, and decide from the measured gap. Under 1 % we answer silently; up to 10 % we answer and state the assumption; beyond that we ask — showing the real number for each option, so the user recognises their intent instead of parsing jargon. Zero extra model calls.

The correction worth mentioning to judges. Percentage alone was the wrong test. The FY2026 fork measures only 7.4 % — below our ask threshold — but 7.4 % of $18B is $1.34 billion. A second trigger now fires on absolute gap (0.5 % of total spend, so it scales with whatever dataset is loaded).

06What to say if asked “why will this survive the real dataset?”

  • Nothing hardcodes the data. Statuses, categories, the fiscal-year boundary and money columns are all introspected at boot into one registry.
  • Detectors disarm themselves. If the new data has no fiscal-year column, that detector switches off. Two reconciliation statuses instead of four and the scope question stops being asked — no code change either way.
  • The swap is one loader. Emit the same seven tables and everything downstream is untouched. Budgeted at 2.5 hours.
